# Live language-switcher route investigation - 2026-09-25

Joey reported translated pages appearing under different paths and with different content. Verified production in a fresh Chromium context on 2026-09-25 at ~22:30 ET.

- English `/miracles/`, selecting Arabic, currently lands at `/miracles/?lang=ar`, not the authored `/ar/miracles/`. Root cause: `translate.js` strips the trailing slash before looking up `locale-routes.js`, whose canonical key is `/miracles/`. The resulting `?lang=ar` invokes client-side machine translation of the English hub while retaining its English canonical. This is a routing bug. Fix checks both the normalized clean route and slash form, and adds an end-to-end test of the English directory hub selector.
- English `/history` -> French `/fr/biographie`; `/saint-charbel-prayers` -> Spanish `/es/oraciones`; `/saint-charbel-feast-day` -> Portuguese `/pt/festa`; and `/miracles/nohad-el-shami` -> Arabic `/ar/miracles/nohad-el-shami` all route correctly to authored guides. Different localized slugs are intentional. `/fr/biographie` -> English goes to the authored `/en/biography` guide rather than the related interactive `/history` page by design.
- For a topic not authored in a chosen language, the English-page selector preserves the path and appends `?lang=<code>`; `/saint-charbel-prayer-for-anxiety` -> Arabic stayed `/saint-charbel-prayer-for-anxiety?lang=ar` with English canonical. Its translation is a runtime service and may fail or lag. The generated Arabic story guide's header instead sends an unserved language to that language's homepage, e.g. `/ar/miracles/nohad-el-shami` -> Spanish `/es/`, not a matching story. This is a fallback by design but can look like an incorrect page. Product decision on visible labeling and parity remains open.
- Authored guide pages are original and often shorter than related English interactive experiences; e.g. the English miracles hub is an interactive, broad report hub, while Arabic `/ar/miracles/` is a concise static guide to the three Church-recognized healings. Hreflang and route labels may imply equivalence to users despite structural difference. Do not present full-parity as shipped.

Checks: Playwright phone tests for slash routing and unserved-language fallback pass. `npm run i18n:check` and `python3 scripts/qa/check_seo.py` pass (132 indexable URLs) on the stage baseline with this fix. Production readback is needed after merge/deploy.
