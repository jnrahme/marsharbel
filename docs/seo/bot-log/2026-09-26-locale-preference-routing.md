# Saved-language routing and authored copy

Based on `stage` 5fd3e4d after Arabic monastery mirrors #280. Fixed a browser-only language mismatch: a stored Arabic preference previously made an English URL render English text under `lang=ar`, RTL layout and an Arabic selector. The script now resolves a saved choice to a real published twin when the current URL is English, preserving other query parameters and the hash. `?lang=en` explicitly pins English. Direct localized URLs continue to render their authored language despite a conflicting stored preference. An English route without a published twin stays English; only an explicit `?lang=...` can invoke the existing runtime fallback. Passive visits no longer overwrite the saved choice; only changing the selector writes it. Bumped the service-worker cache version to replace its cached translation script.

Regression coverage includes English to Arabic monastery and miracle story navigation, the homepage hub, published French/Arabic pages with conflicting preferences, unsupported English pages, explicit English, and unpublished-language runtime fallback. This change does not add any runtime-only page to sitemap or hreflang. Source of route truth is the generated `locale-routes.js` from the published `locales/registry.json`; no new public claim was introduced. Deployment should test with an existing browser's localStorage and service-worker cache as well as a fresh session.
